# GAZEE · Pleos 시연 앱

Android Studio에서 이 `android` 폴더를 엽니다. 저장소 루트에서 먼저 `pnpm install --frozen-lockfile`을 실행합니다. Android Studio에서 Gradle 동기화 후 Pleos Connect 에뮬레이터를 선택하고 Run을 누릅니다. Gradle 빌드가 현재 React 화면을 묶어 APK에 포함합니다.

앱을 열고 화면 아래의 **시연 조작 열기**를 누르면 블랙아이스 제보 수신과 주행 제한 ON/OFF를 시험할 수 있습니다. 차량 주행 제한 상태가 확인되지 않았거나 실제 제한이 켜져 있으면 Android 쪽에서 화면과 음성을 잠급니다. 시연 버튼의 ON/OFF는 실제 차량 제한을 변경하지 않습니다.

뒤차 수신 시 카드와 600ms의 로컬 알림음만 전달합니다. 제보 내용은 사용자가 Gleo에게 요청할 때 `GAZEE_READ_RECEIVED_REPORT` Action을 통해 반환하고 Gleo가 읽습니다. 알림음은 Android AudioTrack을 사용합니다. https://developer.android.com/reference/android/media/AudioTrack 차량 데이터, 게시글 공유와 Gemini 응답은 웹 시연의 Mock 동작을 사용합니다.

## 앞차 제보 → 뒤차 수신

주차된 Pleos에서 앞차 세션에 제보를 등록하고 **시연 조작 열기 → 뒤차로 전환**을 누릅니다. 같은 경로의 뒤차는 전방 850 m 상태로 열립니다. 시연 제어판에서 **450m로 접근**을 누르면 앞차 글의 ID와 제목을 유지해 해당 커뮤니티에 한 번 전달합니다. 역할, 거리, 전송은 한 에뮬레이터 안에서 시연합니다.

`assets/schema.json`의 `GAZEE_CREATE_REPORT`는 Gleo가 전달하는 제보 본문을 받습니다. 앱은 등록 완료 문구 “제보가 등록되었어요.”를 Gleo 음성 응답으로 돌려줍니다. 뒤차가 제보를 수신하면 카드와 알림음만 전달하며 Gleo를 자동 호출하지 않습니다. Pleos에서 GAZEE를 열고 주차 상태에서 Gleo로 제보를 요청합니다. 앱은 Gleo 서명 권한을 가진 호출을 받습니다.

## 실제 음성 제보

Pleos 에뮬레이터의 **Extended Controls → Microphone**에서 호스트 마이크 입력을 켭니다. 차량이 주차 상태일 때 앱의 주행 모드 화면에서 **음성 호출 켜기**를 누르고 마이크 권한을 허용합니다. “제보할게”라고 말하면 제보 화면이 열리고, 이어 말한 내용이 현재 커뮤니티에 등록됩니다. “제보할게, 전방에 낙하물이 있어요”처럼 한 번에 말할 수도 있습니다.

음성 입력은 Pleos SpeechToText `ON_DEVICE`를 먼저 사용합니다. 에뮬레이터에서 Pleos 엔진이 로딩에 실패하면 같은 마이크를 Vosk 한국어 모델로 인식합니다. 모델은 최초 빌드에서 내려받아 APK에 포함하며, 음성은 기기 안에서 처리합니다. [Vosk 한국어 모델](https://alphacephei.com/vosk/models) 호출 대기는 한 번의 듣기 세션으로 제한되며 화면을 벗어나거나 실제 주행 제한이 켜지면 마이크를 종료합니다. **‘제보할게’ 발화 시연** 버튼으로 예시 발화도 계속 시험할 수 있습니다.


## Windows APK 빌드와 음성 출력 확인

프로젝트 루트에서 실행하면 Android Studio의 JDK를 찾아 현재 빌드 프로세스의 JAVA_HOME을 설정합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\android\build-apk.ps1 -Install
```

`-Install`을 생략하면 APK 빌드만 실행합니다. 웹 의존성은 먼저 설치되어 있어야 합니다.

1. 실제 차량 상태가 P인 에뮬레이터에서 GAZEE를 엽니다.
2. **시연 조작 열기 → 알림음 테스트**를 누르면 짧은 두 음의 알림음이 재생됩니다. 재생 시작/완료 또는 실패 원인을 확인할 수 있습니다.
3. Gleo를 호출하고 “가지 앱에 인천대로 진입 지점이 막히고 있다고 도로 제보를 등록해 줘”라고 말합니다. 실제 Gleo를 통한 제보 등록과 등록 완료 응답 경로입니다.
4. Gleo 안내가 끝나면 **시연 조작 열기 → 뒤차로 전환 → 450m로 접근**을 선택합니다. 카드가 표시되고 알림음이 한 번 재생됩니다. 이때 제보 내용을 자동으로 읽지 않습니다.
5. Gleo를 부른 뒤 **“지금 가지 앱에서 방금 받은 도로 제보를 알려줘”**라고 말합니다. 가장 최근에 수신한 제보를 Gleo가 읽습니다. 앱의 “음성 호출 켜기”를 누를 필요는 없습니다.
6. 알림음 실패 시 **알림음 재시도** 버튼이 표시됩니다. 탭 전환, 동일 제보 재수신, 알림음 토글 켜기만으로 기존 제보의 알림음을 반복하지 않습니다. 알림음을 꺼도 Gleo 읽기 요청은 가능합니다.

앱 내부의 **음성 호출 켜기**는 GAZEE 자체 음성 입력 기능입니다. Gleo 완료 응답을 시험할 때는 위 3번처럼 Gleo를 통해 등록합니다.

현재 수신 경로는 Pleos ON_DEVICE와 Android 기본 TTS를 호출하지 않습니다. 기존 TTS 진단 코드와 엔진은 보존했으며, ON_DEVICE 오류 조사 기록은 아래 검증 문서에 남겼습니다.

파일별 변경과 실제 오디오 검증 범위는 [검증 기록](TTS-VERIFICATION.md)에 정리했습니다. 실제 차량 P 상태에서 앱 내 주행 화면을 시연하며, 실제 주행 제한을 우회하지 않습니다.

## 이전 PC 자동 읽기 도우미

현재 흐름에서는 PC 자동 읽기 도우미를 실행하지 않습니다. 기존 수신 이벤트와 대상 고정용 테스트 연결도 앱에서 제거했습니다. Gleo는 사용자의 명시적인 음성 요청에 응답합니다. 과거 도우미 검증 기록은 `TTS-VERIFICATION.md`에 보존했습니다.

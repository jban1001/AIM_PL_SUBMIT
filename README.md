# GAZEE (가지)

**도로에서 발견한 상황을 음성으로 제보하고, 같은 구간에 접근하는 운전자에게 전달하는 Pleos Connect 커뮤니티.**

운전자는 GLEO나 앱의 마이크로 정체, 도로 위험, 주차·충전 상황과 지역 정보를 제보할 수 있습니다. 수신 차량에는 메시지 카드와 짧은 알림음이 도착합니다. 제보 내용은 GLEO에게 읽어 달라고 요청하거나 카드의 **제보글 음성 출력**을 눌러 들을 수 있습니다.

## 주요 기능

| 기능 | 시연에서 확인할 수 있는 동작 |
| --- | --- |
| 제보 등록 | GLEO로 요청하거나 **음성으로 제보** 버튼을 누릅니다. 게시판의 **글 작성**에서는 직접 입력과 받아쓰기를 지원합니다. 등록한 글은 선택한 게시판 맨 위에 표시됩니다. |
| 세 가지 게시판 | **내 차 중심**은 인하대·용현동·학익동 등 미추홀구 주변, **내 목적지 중심**은 김포국제공항 주변, **내 방향 중심**은 계양구에서 공항으로 이어지는 경로의 예시 글을 보여줍니다. |
| 주행 모드 | Pleos 에뮬레이터 디버그 빌드에서 D단 30 km/h 이상이면 주행 모드가 켜지고 게시글 목록과 일반 글 작성이 제한됩니다. 30 km/h 미만이거나 P단이면 게시판이 열립니다. 플랫폼이 제공하는 이용 제한 상태도 별도로 확인합니다. |
| 제보 수신 | 수신 카드에 범주, 제목, 요약, 음성 안내 문장을 표시하고 제보 근거가 있으면 함께 보여줍니다. 수신 알림음이 켜져 있으면 도착 시 짧게 울리고, 제보 읽기는 운전자가 요청할 때 실행됩니다. |

## 시연 방법

1. GAZEE를 열고 첫 화면의 관심 카테고리 설정을 마칩니다. Pleos 에뮬레이터에서는 아래로 스크롤해 **시연 조작 열기**를 펼칩니다.
2. 시연할 유형을 선택합니다. Pleos에서 교통·도로 위험의 **GLEO로 제보**를 누르면 예시 발화가 표시됩니다. 앱의 **음성으로 제보** 버튼으로도 같은 사례를 제보할 수 있습니다. 주차·지역 시연은 **주행 제한 OFF**에서 글 작성과 받아쓰기를 재현합니다.
3. **제보 수신 시연**을 누르면 현재 게시판에 카드가 바로 도착합니다. 앞차의 등록부터 이어서 보려면 시연 문장으로 제보를 등록한 뒤 **뒤차로 전환**을 누릅니다. 약 15초 후 시나리오에 설정된 접근 거리에서 같은 제보를 받습니다.
4. Pleos 에뮬레이터에서 GLEO를 부르고 **“가지 앱에서 방금 받은 도로 제보를 알려줘”**라고 말하거나 수신 카드의 **제보글 음성 출력**을 누릅니다.

| 시나리오 | 제보 카드 | 시연 수신 거리 |
| --- | --- | --- |
| 교통 | 인천대교 진입 구간 교통 정체 제보 | 약 450 m |
| 도로 위험 | 인하대역 3번 출구 방면 1차선 도로 블랙아이스 제보 | 약 100 m |
| 주차 | 비룡 주차장 지하 2층 전기차 충전이 안됨 제보 | 약 450 m |
| 지역 | 미추홀 구청 근처 국밥집 추천 제보 | 약 450 m |

시연 문장과 일치하거나 지원하는 변형 표현을 입력하면 미리 준비한 카드의 제목·태그·요약·근거를 사용합니다. 일반 입력은 입력 내용으로 제목을 만들고 `기타`로 등록합니다. 마이크로 직접 제보할 때는 마지막에 **“제보해줘”**라고 말합니다.

## Pleos Connect 연동

| 연동 | 맡은 역할 |
| --- | --- |
| GLEO App Action | `GAZEE_CREATE_REPORT`가 제보 제목과 발화 정보를 받고, `GAZEE_READ_RECEIVED_REPORT`가 수신 카드의 안내 문장을 GLEO에 반환합니다. 액션은 [App Schema](android/app/src/main/assets/schema.json)에 정의합니다. |
| Pleos SpeechToText SDK 3.3.1 | `ON_DEVICE` 모드로 한국어 음성 제보와 글 작성 받아쓰기를 처리합니다. |
| Pleos TextToSpeech SDK 3.3.1 | **제보글 음성 출력** 버튼을 누르면 `ON_DEVICE` 모드에 카드의 안내 문장 합성을 요청합니다. |
| Android Automotive OS | `CarPropertyManager`로 기어·속도 변화를 읽어 에뮬레이터 주행 모드에 반영합니다. `CarUxRestrictionsManager`로 플랫폼 이용 제한을 확인합니다. |
| Android AudioTrack | 제보 수신 시 짧은 알림음을 재생합니다. 같은 제보 ID에 대한 중복 재생을 방지합니다. |

React·TypeScript·Vite로 만든 화면을 Android WebView에 탑재합니다. 네이티브 코드는 차량 상태, GLEO, 마이크와 오디오를 화면에 연결합니다.

## 실행

### 브라우저에서 미리 보기

Node.js 24와 pnpm을 준비합니다. 브라우저에서는 예시 발화와 제보자·수신자 흐름을 확인할 수 있습니다.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

터미널에 표시된 주소를 엽니다.

### Pleos Connect 에뮬레이터

1. 저장소 루트에서 `pnpm install --frozen-lockfile`을 실행합니다.
2. Android Studio에서 `android/`를 열고 Gradle을 동기화합니다.
3. Pleos Connect 에뮬레이터를 선택해 **Run**을 실행합니다. Gradle이 웹 화면을 빌드해 APK에 포함합니다.

Windows APK 설치, 마이크 설정, GLEO 호출과 음성 오류 확인은 [Android 실행 안내](android/README.md)를 참고하세요.

## 구현 범위와 다음 단계

현재 게시글과 수신 이력은 시연 세션에서 관리합니다. 앞차·뒤차 전환, 접근 거리, 경로별 게시글과 카드의 차량 관측 근거는 시연 데이터입니다. 제보 정리와 범주 지정은 시연 템플릿과 입력 처리 규칙을 사용합니다.

실차 적용 단계에서는 Pleos 위치·내비게이션 SDK로 주변과 경로의 제보를 선별하고, 차종별 지원이 확인된 신호를 관측 근거로 활용할 계획입니다. 예를 들어 정체 제보에는 구간 속도와 반복 정지, 결빙 의심 제보에는 감속과 조향 변화, 충전 제보에는 케이블 연결과 충전 상태를 활용합니다. 실제 차량 간 전달에는 서버의 제보 유효 시간과 중복 안내 처리, 실차에서의 차량 신호·음성 출력 검증이 필요합니다.

## 개발과 검증

- [`src/scenarios/`](src/scenarios/)는 시나리오별 예시 발화와 메시지 카드를 관리합니다.
- [`src/services/boardSeeds.ts`](src/services/boardSeeds.ts)는 세 게시판의 지역별 초기 예시 글을 관리합니다.
- [`src/hooks/`](src/hooks/)는 제보 등록과 수신·알림 흐름을 처리합니다.
- [`android/app/`](android/app/)은 Pleos SDK와 GLEO 브리지를 포함한 Android 앱입니다.

```bash
pnpm build
pnpm exec tsc --noEmit
node --test "tests/*.test.ts"
```

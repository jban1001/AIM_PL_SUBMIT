# ROADTOWN 공통 커뮤니티 · 작성 · 음성 제보 프로토타입

React + Vite + Tailwind v4. 데이터는 메모리에만 존재하며 새로고침 또는 시연 초기화 시 초기화됩니다. 실제 마이크, STT, Gemini, 차량 SDK, 계정 서버, Pleos TTS는 사용하지 않습니다. 브라우저 Speech Synthesis가 지원되면 Mock 제보 문장을 음성으로 읽습니다. 글의 소유권은 현재 시연 세션의 `demo-driver` 식별자로 구분합니다.

## 블랙아이스 수신 · 주행 상태별 화면 시연

1. 초기 화면은 `DRIVING_RESTRICTED`, **내 차 중심** 탭입니다. 상단에는 “주행 중 이용이 제한돼요 / 중요한 제보는 음성으로 알려드려요.”를 표시하고 전체 목록 대신 수신 대기 화면을 보여줍니다.
2. 차량 화면 바깥 **Demo Controls → 블랙아이스 제보 수신 시뮬레이션**을 누릅니다. 현재 선택된 탭에 Mock 앞차 게시글을 등록하고, 약 450 m 접근 이벤트를 전달합니다. 내비게이션 화면 없이 수신 카드와 음성으로 시연합니다.
3. “전방 약 450미터, 성수대교 진입부에 블랙아이스 제보가 있습니다.”를 한 번 안내하고 메시지 카드 한 장을 표시합니다. `차량 데이터로 관측됨` 문구는 **Mock 근거**이며 실제 센서 확인 결과가 아니라는 안내를 카드 아래에 함께 표시합니다.
4. 음성이 끝나도 카드는 남습니다. **내 목적지 중심 → 내 방향 중심 → 내 차 중심**으로 이동하면 기존 카드를 복원합니다. 처음 두 탭은 수신 전까지 빈 상태이며 각각 별도로 수신 이벤트를 시연할 수 있습니다.
5. **주행 제한 OFF**를 누르면 탭은 유지하고 해당 커뮤니티의 전체 게시글 목록을 표시합니다. 수신한 블랙아이스 글도 ID별로 한 번만 들어 있습니다. 다시 ON을 눌러도 카드와 재생 이력은 남으며 자동 음성은 반복하지 않습니다.
6. **시연 초기화**는 앱 세션을 새로 마운트해 수신 이력·재생 이력·Mock 글·초안·오류 설정을 초기화하고 기본 주행 제한/내 차 중심 상태로 돌아갑니다. 진행 중 STT·AI·TTS의 늦은 결과는 반영하지 않습니다.

### 음성 지원과 중복 방지

- 자동 안내는 **새 수신 이벤트**에서만 시작합니다. 탭 선택, 재렌더, ON/OFF, 토글 ON은 재생 트리거가 아닙니다.
- 최초 자동 재생 시도 여부와 완료 상태는 **제보 고유 ID 전역 기준**으로 관리합니다. 같은 원본 제보를 다른 탭에 명시적으로 수신해도 자동으로 다시 읽지 않습니다.
- 브라우저 미지원·자동 재생 제한·음성 엔진 실패 시 카드에 이유와 **시연 음성 재생** 버튼을 제공합니다. 버튼은 사용자 제스처 안에서 브라우저 음성을 다시 시도합니다. 음성을 사용할 수 없으면 **무음 시연**이라고 명시한 파형/상태 시연으로 대체합니다. 실제 소리가 났다고 표시하지 않습니다.
- 주행 제한 해제, 음성 안내 OFF, 기존 음성 제보 입력 시작, 초기화는 진행 중 안내를 중단합니다. 카드는 유지하고 자동 재개하지 않습니다.
- 제한 해제 상태에서 수신한 제보도 보관하지만, 나중에 주행 제한 ON으로 바뀌었다는 이유만으로 읽지 않습니다. 필요한 경우 카드의 수동 버튼을 사용합니다.

## 기존 작성·음성 제보·삭제 흐름

1. **목적지 중심 직접 작성**  
   화면 바깥 `주행 제한 OFF` → 앱의 내 목적지 중심 → `글 작성` → 직접 본문 입력 또는 예시 불러오기 → `등록` → “제보를 정리하는 중이에요” → “제보가 등록되었습니다.” → 대상 목록 상단에 내 제보 표시.
2. **주행 중 내 차 중심에 음성 자동 등록**  
   화면 바깥 `주행 제한 ON` → 앱의 내 차 중심 → 화면 바깥 `‘제보할게’ 발화 시연` → 마이크·파형·발화 텍스트 → 발화 종료 → 자동 AI 처리 → 자동 등록 → 주행 제한 화면 복귀. `주행 제한 OFF`로 전환하면 목록에서 확인할 수 있습니다. 호출어는 본문에 포함하지 않습니다.
3. **게시글 목록에서 본인 글 직접 삭제**  
   등록된 커뮤니티 → 내 제보의 `삭제`를 터치하면 즉시 사라집니다. 삭제 기능에는 차량 상태 조건이 없으며 본인 글인지 여부만 검사합니다. 다른 이용자의 카드에는 삭제 버튼이 없습니다. 기존 주행 중 목록 잠금은 유지하며, 목록이 표시되는 모든 상태에서 같은 삭제 동작을 사용합니다.

차량 상태·발화 호출·수신·초기화·오류 설정은 모두 차량 디스플레이 **바깥** Demo Controls에 있습니다. 좌측 내비게이션과 검정색 계기판은 표시하지 않고 ROADTOWN 패널이 전체 너비를 사용합니다. 450 m 접근은 화면 지도나 실제 위치 연동 없이 Mock 이벤트로 처리합니다. 기존 주차 P / 정차 D 상태는 예외 상태 설정의 차량 상태 선택에서 계속 시연할 수 있습니다.

## 공통 화면과 흐름

- 탭 이름과 순서는 **내 차 중심 / 내 목적지 중심 / 내 방향 중심**입니다. 기존 ID `nearby / destination / direction`을 유지해 작성 대상·시나리오 연결을 보존합니다. 탭별 목록·스크롤 위치·새 글 대기열·수신 이력을 보존합니다.
- **작성/음성 제보 진입 시 등록 대상 고정**: 이후 탭 전환과 범주 분류는 등록 대상에 영향을 주지 않습니다.
- **터치 작성의 마이크**: STT가 본문만 채웁니다. 사용자가 `등록`을 눌러야 AI 처리를 시작합니다.
- 터치 작성 중 주행 제한으로 전환해도 초안을 보존합니다. 그동안 별도 음성 제보를 시작한 경우에도 완료·취소 후 기존 터치 초안과 등록 대상을 복원합니다.
- **주행 음성 제보**: 발화 종료 후 별도 확인·등록 버튼 없이 자동 처리합니다. AI 오류 재시도는 확보한 원문을 사용하며 다시 말할 필요가 없습니다.
- 등록 시도당 Mock Gemini 요청 한 번에 제목·근거·5개 범주 중 하나를 생성합니다. 요청 시점의 차량 필드와 같은 커뮤니티의 이전 글을 스냅샷으로 사용합니다.
- 성공한 글만 즉시 대상 목록에 추가됩니다. 실패 시 원문으로 대체 게시하지 않으며, 원문을 보존합니다. 화면 바깥 호출 카운터와 최근 입력 필드 수로 시연 입력을 확인할 수 있습니다.
- 상세·댓글·좋아요·수정·음성 탭 변경·음성 삭제는 없습니다.
- 주행 중 일반 목록·작성은 가립니다. 해당 커뮤니티의 최근 수신 메시지 한 장만 보이며 음성 안내 설정은 주행 제한 화면에서만 표시합니다. 기존 음성 제보 중에는 수신 안내를 중단합니다.
- 게시글 제목은 한 줄, 범주·경과 시간·근거를 목록에서 확인합니다. 근거가 공백이면 해당 영역을 숨깁니다.
- 20초 갱신은 새 글 안내만 표시하고, 클릭 시 반영합니다. 최근 24시간 글을 20개씩 조회하며 스크롤로 이전 글을 추가합니다.
- 네트워크 단절 시 캐시 목록을 유지하고 갱신을 중단합니다.

## 예외 상태 시연

시연 컨트롤의 설정은 해당 동작을 시작하기 전에 선택하세요.

| 설정                        | 동작                                                                   |
| --------------------------- | ---------------------------------------------------------------------- |
| 음성 인식 실패 · 다음 1회   | “음성을 인식하지 못했어요” → 다시 시도. 글·AI 호출 없음                |
| 발화 내용 부족 · 다음 1회   | “어떤 상황인지 한 문장 더 말해 주세요” → 추가 발화. AI 호출 없음       |
| Gemini 처리 실패 · 다음 1회 | “제보를 정리하지 못했어요” → 원문 보존 → 다시 시도. 실패한 글은 미등록 |
| 차량 데이터 조회 실패       | 차량 필드 제외, AI 처리는 계속. 근거는 공백                            |
| 유사 글 없음                | 빈 유사 글 배열 전달, AI 처리는 계속                                   |
| 네트워크 연결 끊김          | 목록 유지, 등록 시 연결 오류 및 재시도                                 |

음성 인식·내용 부족·Gemini 실패는 다음 1회에만 적용하므로 재시도하면 정상 경로를 확인할 수 있습니다. 차량 데이터·유사 글 설정은 해제할 때까지 유지합니다.

### 상태 분리

| 구분                      | 위치 / 역할                                                                                                 |
| ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `DrivingRestrictionState` | `DRIVING_RESTRICTED / UNRESTRICTED`, 기존 `vehicleState`에서 파생되어 서로 어긋나는 이중 상태를 만들지 않음 |
| `CommunitySelectionState` | `selected`; 상태 ON/OFF와 무관하게 보존                                                                     |
| `CommunityPostData`       | `feeds`; 기존 목록·페이지·새 글·스크롤 상태 유지                                                            |
| `NotificationHistory`     | `useNotificationDelivery.history`; 커뮤니티별 ID 중복 없는 이력                                             |
| `TTSPlaybackState`        | 제보 ID별 queued/playing/played/blocked/unsupported/cancelled 등, 탭별이 아닌 전역 재생 상태                |
| 자동 안내 중복 방지       | 이벤트 시점에 기록하는 ID Set; 탭 렌더 이펙트에서 재생하지 않음                                             |

`CommunityLayout`은 기존 `AppLayout`의 별칭입니다. `CommunityTabs / PostList / PostCard`를 그대로 사용하고, 메시지는 `PostCard`의 compact 변형을 재사용합니다. 상세 페이지나 별도 라우터를 추가하지 않았습니다.

### 수신 시나리오 추가 — 공통 UI 변경 없음

1. `src/scenarios/notifications`에 `ScenarioEventHandler` 계약의 파일을 만듭니다.
2. `createEvent(community, now)`에서 `MockNotificationData`를 반환합니다. 게시글의 **안정적인 고유 ID**, 범주·제목·Mock 근거, 거리, 음성 문장, 출처를 지정하세요. ID에 매번 `Date.now()`를 붙이면 중복 방지가 불가능하므로 사건이 같을 때는 같은 ID를 유지합니다.
3. `notifications/index.ts` 레지스트리에 추가하면 Demo Controls의 이벤트 버튼에 자동 노출됩니다. 공통 메시지 UI와 재생 로직은 수정하지 않습니다.
4. 수신 이벤트는 현재 탭에만 저장합니다. 다른 탭에 자동으로 중복 등록하지 않습니다. 동일 원본 ID가 여러 탭으로 명시적으로 전달되면 각 탭의 카드는 독립적으로 유지하되 TTS는 한 번만 시도합니다.
5. 앞차의 Mock AI 결과는 이 fixture에서 생성하므로 실제 Gemini 요청이나 Mock 서버를 띄우지 않습니다. 기존 작성용 Gemini Mock 호출 카운터와 별개입니다.

### 팀원별 시나리오 추가

1. `Scenario` 계약에 맞는 새 파일을 만듭니다: `id`, `name`, `exampleInput`, `vehicleData`, `examples`, `process(body, context)`.
2. `scenarios/index.ts`에 추가하면 공통 UI의 시나리오 설정에 자동 노출됩니다. 화면별 UI를 따로 만들지 않습니다.
3. 음성 예시·차량 데이터·AI 결과는 해당 시나리오 파일에서만 변경합니다. 등록 대상은 공통 세션의 값으로 유지합니다.
4. `simulation.incomingCount(context)`에서 새 글 알림 조건과 수량을 결정할 수 있습니다.
5. 각 `process`는 단 한 번 호출됩니다. 근거가 없으면 `evidence: ""`, 범주는 교통/도로 위험/주차/지역 정보/기타 중 하나만 반환합니다.

Mock 응답은 등록된 **예시 원문과 일치할 때** 해당 시나리오의 결과를 반환합니다. 임의 입력은 원문을 축약하고 범주를 `기타`, 근거를 공백으로 처리합니다. 키워드 기반 선분류나 실제 Gemini 분류로 가장하지 않으며 원문에 없는 원인·관측을 추가하지 않습니다. 모든 차량 근거에는 시뮬레이션임을 표시합니다.

## 변경 가능한 기본값과 안전

`mockConfig`에서 갱신·페이지·24시간 조회·AI/STT 지연·성공 표시 시간·최소 본문 길이를 변경할 수 있습니다. 최소 8자(공백·일부 문장부호 제외)는 내용 부족 시연용 기본값이며 확정된 언어 이해 기준이 아닙니다. 같은 지역 유사 글 검색은 현재 선택 커뮤니티의 Mock 글로 대체합니다. 실제 지역 검색·차량 데이터 필드 및 방향/목적지 조회 반경은 미확정입니다.

실차 제한은 속도 임계값이 아닌 `CarUxRestrictions`에 연결해야 합니다. 주행 중 탭 터치, 수신 메시지 노출, STT 텍스트 노출, 음성 제보, 자동 TTS·재생 제어는 Pleos 정책 및 앱 심사를 별도로 검증해야 합니다. 현재 코드에는 차량 제어·센서 접근·실제 위치·내비게이션·백엔드 연동이 없습니다.

# GAZEE (가지)

**도로에서 발견한 상황을 음성으로 제보하고, 같은 구간에 접근하는 운전자에게 전달하는 Pleos Connect 커뮤니티.**

운전자는 GLEO나 앱의 마이크로 정체, 도로 위험, 주차·충전 상황과 지역 정보를 제보할 수 있습니다. 수신 차량에는 메시지 카드와 짧은 알림음이 도착합니다. 제보 내용은 GLEO에게 읽어 달라고 요청하거나 카드의 **제보글 음성 출력**을 눌러 들을 수 있습니다.

## 주요 기능

| 기능 | 시연에서 확인할 수 있는 동작 |
| --- | --- |
| 제보 등록 | GLEO로 요청하거나 **음성으로 제보** 버튼을 누릅니다. 게시판의 **글 작성**에서는 직접 입력과 받아쓰기를 지원합니다. 등록한 글은 선택한 게시판 맨 위에 표시됩니다. |
| 세 가지 게시판 | **내 차 중심**은 인하대·용현동·학익동 등 미추홀구 주변, **내 목적지 중심**은 김포국제공항 주변, **내 방향 중심**은 계양구에서 공항으로 이어지는 경로의 예시 글을 보여줍니다. |
| 주행 모드 | Pleos 에뮬레이터 디버그 빌드에서 D단 30 km/h 이상이면 주행 모드가 켜지고 게시글 목록과 일반 글 작성이 제한됩니다. 30 km/h 미만이거나 P단이면 게시판이 열립니다. 플랫폼이 제공하는 이용 제한 상태도 별도로 확인합니다. |
| 제보 수신 | 수신 카드에 범주, 제목, 요약, 음성 안내 문장을 표시하고 제보 근거가 있으면 함께 보여줍니다. 수신 알림음이 켜져 있으면 도착 시 짧게 울리고, 제보 읽기는 운전자가 요청할 때 실행됩니다. |

## 시연 방법

1. Pleos 에뮬레이터에서 GAZEE를 열고 관심 범주를 선택합니다. 네 가지 태그가 섞인 샘플 게시판을 보려면 네 범주를 모두 선택합니다. [Android 실행 안내](android/README.md#주행-모드-확인)에 따라 Virtual Console을 연결합니다.
2. 교통·도로 위험은 GLEO에 “가지 앱에 … 제보해줘”라고 요청하거나 주행 모드에서 **음성으로 제보**를 누릅니다. 주차·지역 정보는 일반 게시판의 **글 작성**에서 직접 입력하거나 받아쓰기로 등록합니다. [시연 발화 예시](android/README.md#등록과-수신-시연)
3. 등록 직후 체크 아이콘과 **“제보가 등록되었습니다.”**가 표시됩니다. 잠시 뒤 주행 모드의 앞차 화면에서 등록 카드를 확인할 수 있고, 등록한 글은 해당 게시판 상단에 올라갑니다.
4. 뒤차를 시연할 때는 아래 PowerShell 명령으로 전환합니다. 수신 카드가 뜨면 GLEO에 **“가지 앱에서 방금 받은 도로 제보를 알려줘”**라고 요청하거나 카드의 **제보글 음성 출력**을 누릅니다.

### 뒤차 전환 명령

Pleos 에뮬레이터 한 대에서 GAZEE를 열고 **앞차 상태로 시연 문장에 맞는 제보를 먼저 등록**합니다. 앱을 열어둔 채 Virtual Console에서 D단으로 30 km/h 이상을 유지하고, 저장소 루트에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\android\demo-vehicle.ps1 -Role rear
```

‘뒤차 선택 완료’가 표시되면 약 15초 뒤 시나리오별 수신 카드와 알림음이 도착합니다. 앞차로 돌아가려면 같은 명령의 인수를 `-Role front`로 바꿉니다. 제보가 저장된 앱 세션에서 실행하세요. 앱을 다시 열었다면 앞차에서 제보부터 등록합니다.

| 시나리오 | 제보 카드 | 시연 수신 거리 |
| --- | --- | --- |
| 교통 | 인천대교 진입 구간 교통 정체 제보 | 약 450 m |
| 도로 위험 | 인하대역 3번 출구 방면 1차선 도로 블랙아이스 제보 | 약 100 m |
| 주차 | 비룡 주차장 지하 2층 전기차 충전이 안됨 제보 | 약 450 m |
| 지역 | 미추홀 구청 근처 국밥집 추천 제보 | 약 450 m |

GLEO와 앱 마이크 모두 시연의 장소와 상황이 일치하면 기존 고정 카드의 제목·태그·요약·근거를 사용합니다. 앱 마이크는 **“제보해줘”**로 입력을 마칩니다. 일반 글은 입력으로 제목을 만들고 주차·교통·지역 정보·도로 위험 중 하나로 분류합니다. 주차·교통·도로 위험 표현을 찾기 어려운 글은 지역 정보로 등록합니다.

## 최근 변경과 트러블슈팅

| 증상 | 원인과 조치 |
| --- | --- |
| “인천대교 현재 정체 중”을 말하면 인식된 문장이 제목으로 올라감 | 시연 규칙이 “현재”가 들어간 짧은 표현을 놓쳤습니다. 교통·도로 위험·주차·지역 정보에 장소와 상황이 맞는 짧은 표현을 추가했습니다. |
| GLEO 제보는 고정 카드로 저장되는데 앱 마이크 제보는 일반 글로 저장됨 | 마이크 인식문 끝에 “재고해줘”, “내 보호해줘” 같은 반복 발화가 붙으면 시연 문장 매칭에 실패했습니다. 끝부분의 알려진 오인식은 시연 판정에서만 정리하고 인식 원문은 보관합니다. 입력이 끝나려면 최종 인식에 “제보해줘”가 필요합니다. |
| 등록 완료 안내가 금방 사라지거나 카드·팝업이 겹침 | 완료 화면에는 체크와 “제보가 등록되었습니다.” 안내를 남겼습니다. 등록 카드는 이후 주행 모드의 앞차 화면과 게시판에서 확인합니다. GLEO 등록 성공 응답에는 제목·요약·완료 문구를 전달합니다. |
| 앞차에서 등록한 뒤 기다리면 수신 카드가 자동으로 뜸 | 등록에 따라 시작되던 자동 수신 타이머를 제거했습니다. 기어와 속도는 Virtual Console에서 조작하고, 수신 시연은 뒤차 전환 명령으로 시작합니다. |
| 샘플 게시판에 한 종류 태그만 많이 보임 | 첫 샘플 글을 네 범주가 섞이도록 배치하고 기존 기타 태그를 재분류했습니다. 시작할 때 한 범주만 선택하면 그 범주의 글만 보이므로 전체 샘플을 보려면 네 가지를 선택합니다. |
| 차량 근거에 기술 설명이 길게 붙음 | 교통·결빙·충전 근거를 관측 내용 위주로 다듬고 앞에 “차량 데이터로 확인결과,”를 붙였습니다. 화면의 시연용 표시는 유지합니다. |

## Pleos Connect 연동

| 연동 | 맡은 역할 |
| --- | --- |
| GLEO App Action | `GAZEE_CREATE_REPORT`가 제보 제목과 발화 정보를 받고, `GAZEE_READ_RECEIVED_REPORT`가 수신 카드의 안내 문장을 GLEO에 반환합니다. 액션은 [App Schema](android/app/src/main/assets/schema.json)에 정의합니다. |
| Pleos SpeechToText SDK 3.3.1 | `ON_DEVICE` 모드로 한국어 음성 제보와 글 작성 받아쓰기를 처리합니다. |
| Pleos TextToSpeech SDK 3.3.1 | **제보글 음성 출력** 버튼을 누르면 `ON_DEVICE` 모드에 카드의 안내 문장 합성을 요청합니다. |
| Android Automotive OS | `CarPropertyManager`로 기어·속도 변화를 읽어 에뮬레이터 주행 모드에 반영합니다. `CarUxRestrictionsManager`로 플랫폼 이용 제한을 확인합니다. |
| Android AudioTrack | 제보 수신 시 짧은 알림음을 재생합니다. 같은 제보 ID에 대한 중복 재생을 방지합니다. |

React·TypeScript·Vite로 만든 화면을 Android WebView에 탑재합니다. 네이티브 코드는 차량 상태, GLEO, 마이크와 오디오를 화면에 연결합니다.

## 실행

### 브라우저에서 미리 보기

Node.js 24와 pnpm을 준비합니다. 브라우저 미리보기에서는 게시판과 글 작성 화면을 확인할 수 있습니다.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

터미널에 표시된 주소를 엽니다.

### Pleos Connect 에뮬레이터

1. 저장소 루트에서 `pnpm install --frozen-lockfile`을 실행합니다.
2. Android Studio에서 `android/`를 열고 Gradle을 동기화합니다.
3. Pleos Connect 에뮬레이터를 선택해 **Run**을 실행합니다. Gradle이 웹 화면을 빌드해 APK에 포함합니다.

Windows APK 설치, 마이크 설정, GLEO 호출과 음성 오류 확인은 [Android 실행 안내](android/README.md)를 참고하세요.

## 구현 범위와 다음 단계

현재 게시글과 수신 이력은 시연 세션에서 관리합니다. 수신은 시연에 등록한 제보를 같은 에뮬레이터에서 다시 받는 방식입니다. 접근 거리, 경로별 게시글과 카드의 차량 관측 근거는 시연 데이터입니다. 제보 정리와 범주 지정은 시연 템플릿과 입력 처리 규칙을 사용합니다.

실차 적용 단계에서는 Pleos 위치·내비게이션 SDK로 주변과 경로의 제보를 선별하고, 차종별 지원이 확인된 신호를 관측 근거로 활용할 계획입니다. 예를 들어 정체 제보에는 구간 속도와 반복 정지, 결빙 의심 제보에는 감속과 조향 변화, 충전 제보에는 케이블 연결과 충전 상태를 활용합니다. 실제 차량 간 전달에는 서버의 제보 유효 시간과 중복 안내 처리, 실차에서의 차량 신호·음성 출력 검증이 필요합니다.

## 개발과 검증

Pleos 에뮬레이터에서 첫 게시판의 네 태그와 제보 근거 문구를 확인했습니다. 앱에 테스트 제보를 넣어 등록 완료 화면과 15초 후 앞차 유지도 확인했습니다. 앱 마이크의 고정 카드 매칭은 화면에서 확인한 인식문을 사용한 테스트로 검증했습니다. 최신 변경의 실제 마이크 입력과 GLEO 등록 응답 재생은 추가 확인이 필요합니다.

- [`src/scenarios/`](src/scenarios/)는 시나리오별 예시 발화와 메시지 카드를 관리합니다.
- [`src/services/boardSeeds.ts`](src/services/boardSeeds.ts)는 세 게시판의 지역별 초기 예시 글을 관리합니다.
- [`src/hooks/`](src/hooks/)는 제보 등록과 수신·알림 흐름을 처리합니다.
- [`android/app/`](android/app/)은 Pleos SDK와 GLEO 브리지를 포함한 Android 앱입니다.

```bash
pnpm build
pnpm exec tsc --noEmit
node --test "tests/*.test.ts"
```
